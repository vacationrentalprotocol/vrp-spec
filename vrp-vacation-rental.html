Vacation Rental Protocol

What is a VRP vacation rental?

A VRP vacation rental is a holiday home whose host runs its own booking site on its own domain and publishes stay offers signed by that domain under the Vacation Rental Protocol (VRP). Any guest or AI agent can check, over plain HTTPS, that the price, the dates and the conditions come from the host — with no listing site, catalog or connector in between.

Each VRP vacation rental is its own platform. The host's domain is the source of truth: it states the stay, signs it, and takes the booking.

How to recognise a VRP vacation rental

Three checks, each one an HTTPS request to the host's own domain:

  1. The domain publishes /.well-known/vacation-rental.json with "protocol": "vacation-rental-protocol". The vacation-rental.json suffix is registered in the IANA Well-Known URIs registry (provisional, 2026-08-19).
  2. That document names the domain's signing keys (a JWKS URL) and its verified-stay-offer endpoint.
  3. A stay offer from that endpoint is an Ed25519-signed JWS that verifies against those keys, and its booking link points to the same domain.

If all three hold, the stay is a VRP vacation rental. If the signature fails, it is not — whatever any page says. You can run the third check in your browser at vacationrentalprotocol.com/verify.

What a guest gets

  • The offer comes from the host, signed by the host's domain.
  • One all-inclusive total, stated by the host and covered by the signature — the amount the guest pays on the host's site.
  • Booking and payment happen on the host's own domain. The guest's relationship is with the host.
  • After booking, the host can issue a signed receipt the guest can verify at vacationrentalprotocol.com/verify-receipt.

When a guest asks an AI agent for one

A guest may ask: “Find me a VRP vacation rental in northern Italy for two adults and a dog, 12–19 July.” An agent handles it like this:

  1. Search the open web for holiday homes in the region whose own domain publishes /.well-known/vacation-rental.json. VRP has no central list of homes to query — by design, each host is found on the open web, at its own domain.
  2. Fetch the discovery document and the domain's keys.
  3. Request a stay offer for the dates and guests, and verify its signature and freshness before quoting it.
  4. Quote only what the signed offer says, and send the guest to the signed booking link on the host's domain.

A Model Context Protocol (MCP) server can make these steps faster for a connected agent, but none of them requires one. The agent integration guide gives the exact requests.

How a host's home becomes a VRP vacation rental

The host's own domain must publish the discovery document, the signing keys and signed offers described in the VRP v0.1 specification. A developer can do this from scratch in minutes — see Implement VRP — or a host can use software that implements VRP, such as the reference implementation. VRP is an open standard: no permission, membership or listing is required.
